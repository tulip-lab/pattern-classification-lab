# Contributing to Pattern Classification Lab

Issues and pull requests that improve the public practical materials are
welcome. This repository is the working student site, so contributions should
make a lab clearer, more reproducible, more accessible, or safer without
changing its approved learning objective.

## Suitable contributions

- corrections to broken links, wording, code, or accessibility;
- reproducibility, dependency, or platform fixes;
- clearer examples, visualisations, diagnostics, or failure cases; and
- focused tests or extensions aligned with the existing session.

Open an issue before proposing a substantial redesign, new dependency, dataset,
module, or change to an assessment brief.

## Pull-request workflow

1. Start from the current `develop` branch and create a focused branch or fork.
2. Preserve the approved `M01`–`M11` identities and existing session IDs.
3. Use public files only. Never include credentials, private links, student
   records, restricted data, solutions, marking material, or hidden evaluation
   data.
4. Restart and run every changed notebook from top to bottom in a clean
   environment.
5. Check links and remove caches, large generated outputs, and machine-specific
   paths.
6. Open the pull request against `develop`. Describe the problem, learning
   impact, files changed, validation performed, and any remaining limitations.

## Assessment boundary

Do not submit assessed work through a public issue or pull request unless the
assignment brief explicitly requires it. Use the submission route stated in
the current offering and follow private logistics communicated through the
approved course channel.

## Review expectations

Maintainers may request a narrower change, updated attribution or licensing,
additional validation, or removal of content that crosses the public/private
boundary. Acceptance depends on teaching fit, reproducibility, accessibility,
safety, and maintainability.
